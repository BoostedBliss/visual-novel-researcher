## 2026-11-10 - StoryboardView Relational Data Processing Bottleneck
**Learning:** The `VisualNovel` data model is highly relational (`VisualNovel` -> `Chapters`, `Scenes`, `Characters`). Accessing these relationships directly inside render loops using `Array.filter` or `Array.find` (e.g., matching scenes to chapters or characters to scene speakers) results in hidden O(N²) scaling overhead. In `StoryboardView`, finding scenes for chapters and characters for scenes on every render caused unnecessary processing during UI updates.
**Action:** When rendering hierarchical, flattened data models like `VisualNovel`, pre-compute relationships in `useMemo` hooks using Hash Maps (e.g., `Map<string, Scene[]>`, `Map<string, Character>`). This transforms O(Chapters × Scenes) filtering and O(Scenes × Characters) lookups into O(N) setup and O(1) render-time access.
